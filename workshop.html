「我发明了一种新的 workshop」
怎么变成一句学术命题

Morrow 学生工作区 · 第二部分 · 2026-11

00你这句话为什么"虚"——不是因为不对，是因为它没说清新在哪里

「我发明了一种新的教学交互模式」这句话在答辩上能唬住人，在审稿人面前一秒破功。因为三个问题都答不上来：

  • 新相对于什么？ 相对于 Schön 讲的 reflective practicum？相对于设计冲刺？相对于「Miro 白板 + 群里发 ChatGPT」？不说清楚参照物，「新」是形容词不是事实。
  • 新模式里哪一个变量变了？ 「AI 和工作坊结合」是功能描述，不是机制。没有变量，就没有因果，也没有实验。
  • 它什么时候会失效？ 没有任何模式是普适的。说不出边界条件，说明你还没把它想成机制，只是把它想成了产品。

这并不是说你的直觉错了。你的直觉很准，只是还没被翻译。下面四步是翻译器。

01学术化四步：命名 → 参数化 → 机制 → 边界

步要产出什么你现在的状态
① 命名给这个形式一个能被人引用的名字，并一句话定义它的公共对象是什么缺。你叫它"新的 workshop"，别人无法引用
② 参数化把它拆成 3–5 个可配置的维度（design space），别人能据此造出别的版本有一半。你的界面里已经有这些参数，但没被写成参数
③ 机制一个可被反驳的因果预测：改动某参数 → 某人的行为/认知改变，并且为什么缺。这是"虚"的主要来源
④ 边界说明它在什么条件下不成立（团队规模、技能阶段、任务类型）缺。但你已经能感觉到（比如高年级可能不需要）

四步做完，你就不再是"我做了个平台"，而是"我提出并刻画了一种形式，并检验了它的一个机制"。前者是作品集，后者是论文。

02关键一步：把"工作坊"重新定义为公共对象

工作坊（studio / crit）之所以是工作坊，从来不取决于桌椅怎么摆、几个人一组，而取决于什么东西被摆到公共面前供人追问。传统工作坊的公共对象是半成品作品，权威解释者是教师，稀缺资源是教师的时间。

AI 进来以后，真正被改掉的是这三件事：

  • 过程第一次变得可读。 谁在第几版改了什么、agent 补了哪一段、团队在哪一步分叉——这些以前只活在硬盘里，现在是一部可以被翻看的日志。可读的过程，本身就可以成为工作坊的公共对象。
  • 批评的稀缺性被解除。 教师的时间不再稀缺，随时能拿到反馈。于是工作坊的组织问题从"排期"变成"可见性设计"：谁看得见谁的中间态、谁的 agent 说了什么。
  • 房间里多了一个没有立场、也没有责任的参与者。 它参与创作，但不能被追责；它产出很快，但对结果没有利害关系。这在教学法上是一个新问题：当相当一部分工作由一个既不是教师也不是学生的第三方完成时，工作坊怎么组织？
你要说的话不是「我把 AI 加进了工作坊」，而是：

「我把工作坊的公共对象，从作品换成了过程。AI 不是这个工作坊里多出来的一个工具，它是让这个过程第一次可以被看见、被追问、被追责的那个条件。」

这句话在答辩上可以用，在论文第一段也可以用。它包含了一个 claim（公共对象转移）、一个条件（可读性由 AI/日志提供）、一个后果（可追责性成为设计问题）。

可以用的名字

推荐：legible studio（可见的工作坊）。备选：process-first crit、instrumented studio。名字只要满足两个条件——能被一句话定义、能和你做的界面挂上钩。定义句式：

A workshop format in which the team's production process — not the finished artifact — is the shared object of critique, and in which an AI collaborator's invocation rights, output visibility, and intervention timing are explicit, configurable parameters.

03参数化：五个维度（你的界面里其实已经都有了）

这是你最省力也最有分量的一步。你现在已经实现了这些差异，只是没把它们写成"设计空间"。

轴取值你平台上对应的地方
A 调用权 谁能请 agent 干活个人私有 / 组内共享 / 教师调用 / 全班共用一个AI 讨论与执行、团队活动与权限
B 可见性 谁看得见 agent 的产出与过程只给调用者 / 组内 / 全班 / 教师独占笔记编辑与留言、成熟项目与多选
C 时机 agent 什么时候说话提交后（事后）/ 被调用才答 / 过程中主动介入AI 讨论与执行 vs 课堂与工作坊
D 角色 你让它扮谁执行者 / 批评者（critic）/ 提问者（Socratic）/ 记录者 / 仲裁者AI 讨论与执行里的多种模式
E 归属 贡献留不留痕无痕 / 有署名 / 有贡献度统计灵动版本叠层 + 埋点

一张 5 轴的表，就是一次设计空间贡献。你不需要证明你的那个点是唯一正确的，你只需要证明这些点之间存在真实差异，而且差异是可预测的。这比"我发明了它"稳得多——它同时把你申请专利式的口吻，换成了研究者的口吻。

04三条机制命题（带可被证伪的预测）

M1把 critic 放在组内共享，会提高低话语权成员的参与，但降低他们对教师 crit 的准备度
为什么
批评指向作品而非人，且随时可用 → 内向的人敢问、不用当众暴露；但也因此把"最后的审判"提前消耗掉了，到真 crit 时已经没有被挑战的紧张感。
怎么测
6 周团队部署，组内共享 critic vs 个人私有 critic（拉丁方）。测：每人发言轮次（日志 + 录音编码）、教师 crit 前 24h 的修改量、学生对 crit 的焦虑与准备度自评。
投哪里
CHI / CSCW（CSCW 走 PACM rolling）。
风险
会被问"这不就是 AI 助教"。答法：区别在角色——助教给答案，critic 只追问；且你的操纵是共享范围，不是有无 AI。
M2agent 调用的私有化，会让团队贡献变得不可归因——而且 AI 越强，偏差越大首推
为什么新
团队协作 + AI 的研究几乎都停在"团队绩效有没有提高"。没人问：AI 是否让"谁做了什么"这件事实质性消失。这是团队特有的问题，不是单人的问题乘以人数。
为什么重要
设计教育的评分单位是团队作品 + 个人成长。如果过程不可归因，评价就退化成"看谁最后提交得多"，而这件事在 agent 时代可以被一个人伪造。这是教学公平问题，不是效率问题。
怎么测
受试内（同一批团队，两种调用可见性），N=12–16 个 4 人团队。测：团队自评贡献分配 vs 教师盲判 vs 日志真实比例，三者的一致性（用 ICC / 偏差绝对值）；再加一次"事后复盘"，看团队能否凭记忆还原谁做了什么。
证据链
一致性下降 + 偏差随 AI 使用强度上升（相关）+ 复盘失败的具体模式（质性，3–4 条轨迹）。
投哪里
CSCW 最合，DIS 次之。
风险
"这是 social loafing 老问题"。答法：老结论是个体懈怠，你的是归因失真——人可能没偷懒，但记录不允许被看见。方向相反，机制不同。
M3过程内主动介入会提高迭代次数但降低收敛——工作坊组织者真正痛的地方
为什么
随时有人给你新可能，团队就永远在发散；而工作坊必须有"定稿"这个仪式。
怎么测
同一任务，主动介入 vs 被动调用。测：版本数、版本间的意图一致性（编码）、是否按期定稿、成员对"被催"的感受。
投哪里
DIS full paper 或 Pictorials（这个话题很适合图文并说）。
风险
结论可能太常识。要靠机制解释撑起来：不是"AI 让人发散"，而是"主动介入把决定权从团队手里悄悄拿走了"。

先做 M2。 理由：它是团队层面独有的问题（别人做不了，因为要有真实团队 + 真实日志）、成本最低（不需要重做系统，只需要两种可见性 + 一份问卷）、而且即使结果是"没有偏差"，也照样能发——那等于说 AI 没有破坏教学公平，是个有价值的公共结论。

05文献锚点：五条线，每条三篇（读这三篇就够撑起 related work 的骨架）

  • 工作室/反思性实践 —— Schön（1983 / 1987）的 reflective practicum 是整个 studio 教学法的理论源头，你的"crit 是仪式"这句话必须挂在他身上。再补一篇近年 design critique 的实证研究（在 DIS/CHI 上找 "critique" 关键词，2022 年后，让它替你说明批判机制至今没被参数化）。
  • 共同可见性 awareness —— Dourish & Bellotti（1992, CSCW）关于共享工作空间里"知道别人在做什么"的经典分析。你的整个 B 轴都是它的当代版本，引用它就是把自己的贡献缝进 CSCW 主干。
  • 课堂编排 orchestration —— Dillenbourg（2013）与 Sharples（2013）关于教师如何在真实课堂里调度注意力的论述。你的"教师时间不再是稀缺资源"这句判断，是对他们的直接回应。
  • 边界物与分布式认知 —— Star & Griesemer（1989）、Hutchins（1995）。用来论证"过程日志成为新的边界物"这一句。别滥用，一段话够。
  • 团队贡献与懈怠 —— Latané, Williams & Harkins（1979）social loafing 是你要正面对话的老对手；再补一篇 CSCW 上关于"个人贡献可见性"的工作。M2 的说服力全靠这条线。

这些是我能负责的锚点；具体篇名请去 Google Scholar 核对一遍再写进参考文献。近两年"AI in design education / AI critique"的短文很多，务必自己扫一遍最新的，免得被审稿人指出漏引。

06把"形式"当贡献，需要过哪几道关

如果 P（这页的 workshop）当主角、实验当配角，那它是一篇 Artifact / Methodological 贡献。这类论文的过关条件跟实证论文不一样：

  1. 可复现的形式：把 legible studio 写成一份别人能照着搭的规格（五轴的取值 + 每个轴上你的选择及理由 + 替代方案）。不是截图，是规格。
  2. 非显然性：必须有一段"为什么不能更简单"——比如为什么不能就用微信群 + ChatGPT。审稿人最爱问这个，答不上来说明形式本身不成立。
  3. 一个证明它真的不同的证据：哪怕只有 M2 一项，也足够。形式论文不需要全证据，需要一条硬的。
  4. 可迁移：说明它能不能用于建筑、工业设计、或非设计专业。能迁移，才叫形式；只能在你课上用，那叫课程。
别做的事：不要说「invent」。英文里 we propose / we present / we characterize 站得住，we invent 一站不住；而且"发明"会把评审的注意力引到优先权之争上，那是你必输的战场——你要的是解释力，不是首发权。

07可以直接抄的措辞

中文摘要第一句（毕设/答辩用）

本文提出「可见的工作坊」（legible studio）：一种以团队协作过程而非最终作品作为公共批评对象的设计教学工作坊形式，并把 AI 协作者的调用权限、输出可见性与介入时机确立为三个可配置参数。通过为期 X 周、N 个团队的部署研究，本文发现……

英文摘要

We present the legible studio, a workshop format in which the team's production process — rather than the finished artifact — becomes the shared object of critique, and in which an AI collaborator's invocation rights, output visibility, and intervention timing are treated as explicit, configurable design parameters. In a six-week deployment with N student teams, we find that…

答辩时的一句话

「我不是把 AI 加进了工作坊，我是把工作坊的公共对象从作品换成了过程。AI 不是多出来的一个工具，它是让这个过程第一次可以被看见、被追问的条件。」

08审稿人会怎么打你（提前想好答案）

攻击你的回应
"这不就是 Miro + ChatGPT / 一堆 SaaS 拼起来的？"区别在公共对象与可见性被当成参数，而不是功能相加。给五轴表，指出商业工具在其上都是固定点。
"AI 助教早有人做了。"角色不同（critic/提问者 vs 答题者），且你操纵的是共享范围与时机，不是有无。
"一个班，N 太小，不能外推。"明写 instrumented case study / design deployment，贡献是机制与设计空间，效应量作为方向性证据。附上日志规模。
"过程可见会不会让学生不敢试错？"这恰恰是 M1/M2 要测的东西，把它写进研究问题，而不是藏起来。你已经有一个可调参数（B 轴）专门处理它。
"教育研究该投 CSCL 不是 CHI。"你的对象是交互形式而非学习结果，CHI/DIS/CSCW 正当；同时挂一篇 CSCL 做备选。
一句话：把「我发明了一种工作坊」换成「我提出了一种把过程当作公共对象的工作坊，并把它拆成五个可调参数，其中可见性—归因这一条我做了实证」。前一句是自述，后一句是贡献。两者做的是同一件事，只有后者能被人引用。
